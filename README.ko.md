# % 채점학 · Percent Grading

**타당한 추론을 인정하면서도, 근거 없는 결론을 드러내는 채점 프로그램입니다.**

[English](README.md) | [한국어](README.ko.md) | [Rust 실행 안내](docs/RUST_GUIDE.md) | [영문 교재](book/Percent-Grading-Textbook.md)

제안자: **김유빈(Yubin Kim)**. 현재 구현은 **Rust 0.2.0**이며, 초기 Python 0.1.1 교육용 프로토타입도 보존합니다.

## 왜 만들기 시작했는가

정답과 다른 답안에도 올바른 구성 요소, 타당한 원리, 특정 조건에서 성립하는 결론이 있을 수 있습니다. 정답·오답이라는 하나의 표시로는 이런 차이가 사라집니다.

출발점은 A라는 답을 요구할 때 A만 인정해야 하느냐는 질문이었습니다. 다른 기호가 A의 일부 구성 요소를 공유한다면 그 부분을 기록할 수 있지만, 그것만으로 전체 기호가 A가 되지는 않습니다.

> 이 답안에서 무엇이 맞고, 무엇이 틀렸으며, 어떤 조건에서 성립하고, 무엇을 아직 판단하지 못했는가?

기존에도 부분점수와 분석적 채점 기준은 존재합니다. 이 프로젝트는 명시적인 언어 규칙과 AI를 결합해 더 다양한 관점을 일관되고 검토 가능한 방식으로 적용하는 방법을 연구합니다.

## Rust 프로그램의 작동 방식

1. 실제 [RelSpec/AHAA 컴파일러](https://github.com/kimyubin33/relspec-lang)로 채점 규칙을 검사합니다.
2. 채점 전용 구조와 제약을 추가로 검증하고, SHA-256 식별자로 규칙을 고정합니다.
3. **OpenAI와 Claude 두 AI만** 사용해 미리 정한 판정 항목을 선택하고 답안 근거를 인용하게 합니다.
4. 임의의 기준·판정 항목·숫자 점수나 답안에 없는 인용은 거부합니다.
5. 두 AI가 같은 판정 항목에 동의한 기준을 확정합니다.
6. 프로그램이 정해진 배점으로 계산하고, 불일치와 실행 기록을 보존합니다.

AI는 근거를 판정하고, **점수의 허용 범위와 계산은 Rust가 통제합니다.** 두 AI의 언어 해석까지 항상 같게 만들 수는 없습니다. 서로 다르면 평균으로 덮지 않고 검토 대상으로 남깁니다. 저장된 실행은 AI를 다시 호출하지 않고 재생할 수 있습니다.

AHAA의 고유 문법 키워드는 한글을 유지합니다. 예제의 식별자와 설명, 프로그램 출력, 기술 문서, 교재는 영어입니다.

## 사과 예시

“사과는 무슨 색인가?”만으로는 대상과 조건이 충분히 정해지지 않습니다. 예제는 넓은 파장대의 백색광 아래에서 관찰하는 붉은 껍질의 사과를 지정하고, 색과 이유 및 관련 조건을 설명하도록 요구합니다.

| 답안에 나타난 내용 | 평가하는 항목 |
|---|---|
| 지정한 사과가 빨갛다는 결론 | 문제 의도 충족 |
| 반사와 흡수 등 관련 원리 | 원리의 타당성 |
| 그 원리에서 해당 사과의 색을 도출하는 연결 | 추론의 타당성 |
| 관찰 조건이나 바뀐 상황의 구분 | 조건의 명시 |
| 검증 가능한 미래 가설이나 대안 제시 | 별도의 미래 탐색 점수 |

“사과는 파랗다. 빛이 반사되기 때문이다”에는 맞는 일반 원리가 들어 있어도, 지정한 조건에서 파란색이라는 결론이 도출되지는 않습니다. 파란 조명을 비춘다는 이유만으로 붉은 물체가 반드시 파랗게 보이지도 않습니다. 어둡게 보일 수 있으므로 표면·조명·영상 변환 등의 조건을 구체적으로 밝혀야 합니다.

“빨간색”이라는 짧은 답은 색을 식별하는 항목을 충족합니다. 다만 이 예제는 이유까지 설명하라고 미리 요구하므로, 쓰지 않은 설명을 보여 주었다고 간주하지 않습니다. 단순히 색만 묻는 원래 문제에 추론 배점을 뒤늦게 추가해서는 안 됩니다.

## 퍼센트가 뜻하는 것

현재 과제의 점수는 의도·원리·추론·조건에 관한 명시적 기준의 충족도입니다. 미래 탐색 점수는 가설과 대안이 얼마나 구체적이고 검증 가능하게 제시되었는지 나타냅니다. **미래 점수는 현재 답의 정답 점수를 올리지 않습니다.**

이 수치는 절대적 진리의 비율이나 미래 실현 확률이 아닙니다. 불일치나 미판정 항목에는 범위를 표시합니다. 그 범위도 두 AI의 공통 오판까지 포함하는 통계적 신뢰구간은 아닙니다.

여러 이론은 고정된 기준의 판단에 도움을 주며, 비슷한 이론 수천 개를 나열했다고 배점이 늘어나지는 않습니다. 현재는 명시적으로 등록한 관점을 사용하고, 대규모 이론 자동 검색은 후속 단계입니다.

## API 없이 실행

최신 안정 Rust 도구를 설치하고 저장소를 복제한 뒤, 저장소 폴더에서 실행합니다.

```text
cargo build --locked
cargo run --locked -- compile policies/apple.aha --out local-runs/apple.lock.json
cargo run --locked -- demo local-runs/apple.lock.json examples/rust/apple-blue.fixture.json
cargo test --locked
```

컴파일 명령은 기존 잠금 파일을 덮어쓰지 않습니다. 이미 만든 파일을 재사용하거나 규칙을 바꾼 뒤 새 출력 경로를 지정합니다.

데모 판단은 **사람이 구성한 설명용 예제**입니다. 실제 AI가 생성한 벤치마크 결과가 아닙니다. 빨간색 답안, 미래 가설, 두 AI의 불일치 예제도 포함합니다.

## OpenAI와 Claude 연결

환경변수 `OPENAI_API_KEY`와 `ANTHROPIC_API_KEY`를 설정하고 각 API 계정에서 지원하는 모델 ID를 지정합니다.

```text
cargo run --locked -- grade local-runs/apple.lock.json examples/rust/apple-blue.txt --openai-model YOUR_OPENAI_MODEL --claude-model YOUR_CLAUDE_MODEL
```

실제 채점은 두 API를 호출하며 사용료가 발생할 수 있습니다. ChatGPT 구독과 API 이용은 별개입니다. 다른 공급자나 임의의 API 주소를 추가하는 옵션은 없습니다. 재시도 횟수·시간·출력 토큰·응답 크기를 제한하지만, 정액 비용을 보장하는 기능은 아닙니다.

실행 기록, 재생, 오프라인 판단 파일 처리와 오류 동작은 [영문 Rust 안내서](docs/RUST_GUIDE.md)에 설명합니다. 인증키는 채점 규칙이나 결과 파일에 저장하지 않습니다.

| 기능 | 상태 |
|---|---|
| Rust CLI와 실제 RelSpec/AHAA 컴파일 | 구현 |
| 고정된 채점 규칙·판정 항목·내용 식별자 | 구현 |
| OpenAI Responses 및 Claude Messages API 연결 | 구현 |
| 두 AI의 일치 검사와 정확한 답안 인용 확인 | 구현 |

| 실행 기록 재생과 오프라인 예제 | 구현 |

오프라인 테스트는 프로그램이 정한 규칙대로 동작하는지 검증합니다. 실제 모델의 정확도나 교육적 효과까지 입증하지는 않습니다.

## 기대 효과와 연구 원칙

타당한 대안 인정, 구체적인 피드백, 드러나는 불확실성, 검토·재생 가능한 결정을 목표로 합니다. 이는 검증할 기대 효과이며 이미 측정된 성능 주장은 아닙니다.

조건을 먼저 명시하고, 실제로 쓴 내용에 근거해 평가합니다. 맞는 부분과 실패한 결론을 함께 남깁니다. 기준이 바뀌면 버전을 바꾸고 영향을 받는 답안을 일관되게 재평가합니다. 반례와 불리한 결과도 공개합니다.
